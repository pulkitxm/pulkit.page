## What I build

### Landing pages

One page with one job. We agree on the message and the structure first, then I design and build around it. Usually live in one to two weeks.

### Websites

Multi-page sites with a real design system behind them, so the tenth page still looks like the first. Search and performance are part of the build, not a pass at the end. A CMS if you want to edit things yourself.

### Web and mobile apps

Full products: accounts, dashboards, backend APIs, payments, third-party integrations. Mobile is React Native, so iOS and Android come out of one codebase.

### Performance work

Your product already exists and it's slow. I measure Core Web Vitals, cut bundle size, fix what's blocking the render, and show you the before and after numbers.

### Design and the odd jobs

Wireframes through to a component library and a clean handoff. Alongside that, the work a launch tends to drag in: automation, internal tooling, and short video cuts for social.

## Scope and timelines

Most work is fixed price against a scope we agree up front. After the first call you get a written proposal with the plan, the timeline, and the cost. Ongoing work can run as a monthly retainer instead.

| Scope             | What it covers                                        | Typical timeline |
| ----------------- | ----------------------------------------------------- | ---------------- |
| Landing page      | One page, messaging and structure, analytics wired up | 1 to 2 weeks     |
| Full website      | Multi-page site, component library, optional CMS      | 2 to 4 weeks     |
| Web or mobile app | Auth, dashboards, backend APIs, cross-platform mobile | 4 to 8 weeks     |

### Included in every project

- Clean, readable code another developer can pick up
- Responsive design down to small screens
- Search metadata and Core Web Vitals handled
- Deployed to production, not handed over as an archive
- Documentation and a walkthrough at handoff
- Thirty days of post-launch support for fixes
- Full ownership of the source code

## How we work

1. **Discovery.** The goal, how you'll know it worked, the real constraints, and what fits in a first release.
2. **Design.** Structure and UI direction, agreed before anything gets built.
3. **Build.** Implementation with performance and accessibility in mind, and progress you can look at rather than take on trust.
4. **Launch and iterate.** QA, deploy, handoff, then changes driven by what real usage shows.

### This works best if you

- Have a clear vision, or are happy to be guided to one
- Can make a decision when one is needed
- Would rather get it right than get it fast
- Want to see the work as it happens
