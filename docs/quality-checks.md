# Quality checks and their limits

[Documentation index](index.md)

## Multiple independent layers

The checks catch structural mistakes, policy violations, stale generated output, and many metadata errors. They do not prove accessibility, tutorial accuracy, live availability, or correct behavior in every browser. This guide describes the current merged implementation at the [documented snapshot](maintenance-and-snapshot.md).

## Formatting and source policy

[biome.json](../biome.json) enables space indentation, two spaces, 100-column width, LF endings, recommended rules, all configured correctness/accessibility/security presets, and explicit strict style/suspicious rules. It excludes dist, extras, node\_modules, and font assets; VCS ignore rules also apply. HTML support is experimental, supports template interpolation, and formats void tags as self-closing. `lint` uses `--error-on-warnings`.

Examples of enforced code rules include unused imports/variables, loose equality, `var`, debugger, focused/skipped tests, explicit `any`, CommonJS/default exports, parameter assignment, and missing braces. CLI scripts may use console and Node modules and recognize the Bun global. The Qwik lexical-scope rule is off; Biome unresolved-import checking is off in favor of the custom checker. The old fixture suppressions have been removed. No source-comment exceptions are used for tests.

Biome is not the Markdown/YAML formatter in this project. [check-content.mjs](../scripts/check-content.mjs) uses Remark/GFM and YAML to compare canonical formatting. `--write` only rewrites files with no content errors. It canonicalizes metadata and body separately, with dash bullets, asterisk emphasis, backtick fences, and stable YAML wrapping. This may remove YAML comments when rewriting; the source-comment policy independently disallows comments. Unknown fields and invalid YAML are not silently fixed away.

The strict content pass rejects duplicate YAML keys, parser warnings, explicit tags, anchors, aliases, wrong schema/types, invalid dates, raw HTML, skipped/duplicate headings, unlabeled fences, empty alt text/link labels, unsafe URLs, malformed directives, BOMs, CRs, and noncanonical newlines. Documentation needs exactly one H1. It validates link syntax and labels but does not verify documentation link targets or meaningful quality of alt text. Reference-style Markdown may be parsed differently when malformed; do not treat its undefined-reference walk as a complete Markdown diagnostic engine.

The current [comment scanner](../scripts/check-comments.mjs) uses Tree-sitter grammars, YAML concrete-syntax tokens, Remark trees, parse5 HTML trees, and small SQL/hash/Mermaid lexers. Generated `<code>` text is collected from the full subtree so classed highlight spans do not hide comments. Article code blocks under `content/blogs/` and rendered article code under `pages/blogs/` preserve comments and skip code-language scanning. Frontmatter, actual HTML comments, and executable script/style elements remain checked. Other documentation examples are scanned; unsupported types fail closed. Only an initial shebang is exempt in scanned source. [Repository policies](repository-policies.md) describes the boundaries.

## Repository checks

The repository, content, and comment CLIs use `git ls-files --cached --others --exclude-standard --deduplicate` and skip nonexistent paths. They inspect tracked and nonignored untracked files in the working checkout. In the pre-commit snapshot, that file universe becomes staged content. Ignored local reference/output/dependency trees are outside those Git-based inventories unless force-tracked.

[check-repository.mjs](../scripts/check-repository.mjs) rejects symlinks, case/NFC collisions, temporary suffixes, certain forbidden tracked paths, and invalid source path spelling. The filename rule applies specifically under content/layouts/scripts/docs, with `_site.md` excepted. `.DS_Store`, dist, node\_modules, and exact `.env` names are forbidden; this is not a comprehensive secret-file detector for every possible environment filename.

Files are capped at 2 MiB except selected gif/webp/png/jpg/pdf media beneath `assets/content/`, which allow 5 MiB. NUL-containing or empty files skip text-ending checks; other files reject CRLF and require a final newline. This binary heuristic is not MIME validation, image optimization, or malware detection. Empty `.nojekyll` is allowed.

## Rendered output and HTML

`check:generated` recomputes all HTML, PNG cards, sitemap, and robots output and compares bytes. It catches missing/stale/extra output, route collisions, and production-mode orphan HTML outside pages. Source asset contents are not directly synchronized by this check, except where they influence generated bytes, such as the card font. URL existence and metadata validation are separate checks. Nonproduction checks inspect only their selected output tree for orphan HTML.

`check:layouts` expands every layout with representative values and applies html-validate. `lint` validates real `pages/**/*.html` as well. [.htmlvalidate.json](../.htmlvalidate.json) extends recommended validation, requires lowercase doctype, forbids inline style, prefers self-closing void tags, and disables SRI requirements. Sample layout validation does not cover every possible metadata/body combination, and static HTML rules are not a browser accessibility audit.

Raw HTML is escaped during rendering, metadata values are escaped, and selected generated URL attributes use `safeUrl`. Nevertheless, the default Marked link renderer is not a universal sanitization boundary: the strict content check must also run. This repository expects trusted, reviewed authored content; generation alone is intentionally not the whole policy enforcement layer.

## Imports and links

[check-imports.mjs](../scripts/check-imports.mjs) parses `theme.js` and immediate JS/MJS files under scripts, then resolves top-level static imports and re-exports with `createRequire`. Node builtins and `bun:test` in test files are exempt. It does not check dynamic imports, nested future directories, missing exported symbols, TypeScript types, browser globals, or runtime API behavior. No typecheck package command exists.

[check-site.mjs](../scripts/check-site.mjs) walks built files and scans quoted HTML href/src attributes plus CSS `url(...)`. For local references it checks containment within the build root and existence, accepting directory index files for extensionless paths. It rejects JavaScript URLs and path escapes. It skips HTTP(S)/other protocol-relative external references, mailto/tel/data, and fragment-only references; query/hash suffixes are stripped before local lookup.

It does not fetch external URLs, inspect fragment IDs, parse JavaScript-generated links, cover `srcset`, decode every URL/HTML entity case, or validate the semantics of remote demonstration links. Its regex-based extraction is useful coverage for this simple output, not a complete browser URL model. Documentation cross-links are outside the deployment check and should be checked separately when docs change.

## Regression coverage

| Test file                                                   | Covered behavior                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [generate.test.js](../scripts/generate.test.js)             | Staged snapshot vs unstaged repair; recursive routes; missing/stale/orphan HTML; excluded reference/build trees; collisions and MDX; build rendering and copying; partial/shared metadata invalidation; placeholders/cycles; escaping and heading IDs; list sorting/limits; malformed metadata/directives; clean boundaries |
| [highlight.test.js](../scripts/highlight.test.js)           | Build-time fence highlighting, plain unknown languages, theme token CSS variables, and comment scanning through classed spans                                                                                                                                                                                               |
| [format-code.test.js](../scripts/format-code.test.js)       | Generate-time fence hygiene and Biome formatting, invalid-snippet fallback, literal text fences, Markdown source-byte preservation, highlighter reconstruct on formatted text                                                                                                                                               |
| [check-content.test.js](../scripts/check-content.test.js)   | Canonical formatting, schema/path/date/layout rejection, heading and URL policy, shared metadata, duplicate YAML/aliases, code preservation, GitHub YAML `on` key                                                                                                                                                           |
| [check-comments.test.js](../scripts/check-comments.test.js) | Language-aware comment detection, embedded examples, quoting/heredocs, forbidden directives, unknown-language rejection, and em-dash detection                                                                                                                                                                              |

Tests use disposable filesystems/Git repositories and local server fixtures. The hook test substitutes a small fixture CI command to test index behavior without recursively running production CI. There is no coverage threshold. Server integration tests cover request-time rendering, routing, watcher invalidation, metadata dependencies, error recovery, and explicit port failures. There are no browser/theme interaction tests, external-link monitoring, importer end-to-end preservation tests, visual regression baselines, or remote deployment smoke tests.

Shell syntax checks do not simulate runtime failure paths. Actionlint and zizmor run in the separate GitHub workflow job, not local CI. A passing local command therefore covers a narrower environment than all remote jobs. Recommendations for addressing relevant gaps are in [maintenance](maintenance-and-snapshot.md), clearly separated from implemented checks.

The policy update also adds [policy-ci.test.js](../scripts/policy-ci.test.js), which verifies that force-tracked ignored files are scanned without writes and that Knip rejects unused files, exports, and dependencies.

## SEO and newer regression checks

[check-seo.mjs](../scripts/check-seo.mjs) validates built `dist/` against current page metadata and the resolved origin. It checks selected exact meta values, title, canonical count, H1/main counts, JSON-LD identifiers and relationships, article facts when a BlogPosting is present, PNG signature/dimensions, sitemap membership, robots sitemap advertisement, and same-origin absolute href existence. See [SEO and environments](seo-and-environments.md) for limits. This is local consistency validation, not a search-engine rich-result test.

[seo.test.js](../scripts/seo.test.js) covers safe JSON, graph types, ancestors/related ranking, deterministic cards, and rejection of wrong canonical/meta/JSON/PNG data. [site-origin.test.js](../scripts/site-origin.test.js) covers CNAME changes, environment defaults, URL rejection, and output-directory restrictions. [dev.test.js](../scripts/dev.test.js) runs a real Vite server and covers lazy rendering, edit recovery, concurrent requests, redirects, crawler files, deleted routes, malformed URLs, and explicit port validation. [policy-ci.test.js](../scripts/policy-ci.test.js) checks force-tracked ignored files and Knip failures for unused files, exports, and dependencies. Comment tests explicitly protect the article-example exception.
