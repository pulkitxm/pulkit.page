# Quality checks and their limits

[Documentation index](index.md)

## Multiple independent layers

The checks catch structural mistakes, policy violations, invalid built output, and many metadata errors. They do not prove accessibility, tutorial accuracy, live availability, or correct behavior in every browser. This guide describes the current merged implementation at the [documented snapshot](maintenance-and-snapshot.md).

## Formatting and source policy

[biome.json](../biome.json) enables space indentation, two spaces, 100-column width, LF endings, recommended rules, all configured correctness/accessibility/security presets, and explicit strict style/suspicious rules. It excludes dist, extras, node\_modules, and font assets; VCS ignore rules also apply. The single root configuration covers every workspace, and `@pulkit/code` uses the same file when formatting fences and generated HTML. HTML support is experimental, supports template interpolation, and formats void tags as self-closing. `lint` uses `--error-on-warnings`.

Examples of enforced code rules include unused imports/variables, loose equality, `var`, debugger, focused/skipped tests, explicit `any`, CommonJS/default exports, parameter assignment, and missing braces. CLI scripts may use console and Node modules and recognize the Bun global. The Qwik lexical-scope rule is off; Biome unresolved-import checking is off in favor of the custom checker. The old fixture suppressions have been removed. No source-comment exceptions are used for tests.

Biome is not the Markdown/YAML formatter in this project. [check-content.mjs](../tooling/checks/src/check-content.mjs) uses Remark/GFM and YAML to compare canonical formatting. It recognizes page sources under any `apps/<app>/content/` directory (and the engine's test fixture) and validates embed syntax with the parsers exported by `@pulkit/embeds`. `--write` only rewrites files with no content errors. It canonicalizes metadata and body separately, with dash bullets, asterisk emphasis, backtick fences, and stable YAML wrapping. This may remove YAML comments when rewriting; the source-comment policy independently disallows comments. Unknown fields and invalid YAML are not silently fixed away.

The strict content pass rejects duplicate YAML keys, parser warnings, explicit tags, anchors, aliases, wrong schema/types, invalid dates, raw HTML, skipped/duplicate headings, unlabeled fences, empty alt text/link labels, unsafe URLs, malformed directives, BOMs, CRs, and noncanonical newlines. Documentation needs exactly one H1. It validates link syntax and labels but does not verify documentation link targets or meaningful quality of alt text. Reference-style Markdown may be parsed differently when malformed; do not treat its undefined-reference walk as a complete Markdown diagnostic engine.

The current [comment scanner](../tooling/checks/src/check-comments.mjs) uses Tree-sitter grammars, YAML concrete-syntax tokens, Remark trees, parse5 HTML trees, and small SQL/hash/Mermaid lexers. Generated `<code>` text is collected from the full subtree so classed highlight spans do not hide comments. Article code blocks under `apps/<app>/content/blogs/` preserve comments and skip code-language scanning. Frontmatter, actual HTML comments, and executable script/style elements remain checked. Other documentation examples are scanned; unsupported types fail closed. Only an initial shebang is exempt in scanned source. [Repository policies](repository-policies.md) describes the boundaries.

## Repository checks

The repository, content, and comment CLIs use `git ls-files --cached --others --exclude-standard --deduplicate` and skip nonexistent paths. They inspect tracked and nonignored untracked files in the working checkout. In the pre-commit snapshot, that file universe becomes staged content. Ignored local reference/output/dependency trees are outside those Git-based inventories unless force-tracked.

[check-repository.mjs](../tooling/checks/src/check-repository.mjs) rejects symlinks, case/NFC collisions, temporary suffixes, certain forbidden tracked paths, and invalid source path spelling. The lowercase kebab-case filename rule applies under `apps/<app>/content/`, `apps/<app>/layouts/`, `packages/<package>/src/`, `tooling/<tool>/src/`, and `docs/`, with `content/_site.md` excepted. `.DS_Store`, dist, node\_modules, and exact `.env` names are forbidden; this is not a comprehensive secret-file detector for every possible environment filename.

Files are capped at 2 MiB except selected gif/webp/png/jpg/pdf media beneath `apps/<app>/assets/content/`, which allow 5 MiB. NUL-containing or empty files skip text-ending checks; other files reject CRLF and require a final newline. This binary heuristic is not MIME validation, image optimization, or malware detection.

## Rendered output and HTML

Generated HTML, PNG cards, sitemap, and robots output are never committed. `bun run build` renders them into `apps/page/dist/` from the current sources, so there is no committed output to drift out of date. Route collisions and unsupported MDX fail the build. URL existence and metadata validation are separate post-build checks.

`check:layouts` expands every app layout with representative values and applies html-validate. `check:html` runs html-validate on the built `dist/**/*.html` of each app; Turbo runs it after `build`. [.htmlvalidate.json](../.htmlvalidate.json) extends recommended validation, requires lowercase doctype, forbids inline style, prefers self-closing void tags, and disables SRI requirements. Sample layout validation does not cover every possible metadata/body combination, and static HTML rules are not a browser accessibility audit.

Raw HTML is escaped during rendering, metadata values are escaped, and selected generated URL attributes use `safeUrl`. Nevertheless, the default Marked link renderer is not a universal sanitization boundary: the strict content check must also run. This repository expects trusted, reviewed authored content; generation alone is intentionally not the whole policy enforcement layer.

## Imports and links

[check-imports.mjs](../tooling/checks/src/check-imports.mjs) parses every Git-listed `.js` and `.mjs` module under `apps/`, `packages/`, and `tooling/` (outside `node_modules`), then resolves top-level static imports and re-exports with `createRequire` from each file's own location, so workspace package names resolve exactly as they do at runtime. Node builtins and `bun:test` in test files are exempt. It does not check dynamic imports, missing exported symbols, TypeScript types, browser globals, or runtime API behavior. No typecheck package command exists.

[check-site.mjs](../packages/engine/src/check-site.mjs) walks built files and scans quoted HTML href/src attributes plus CSS `url(...)`. For local references it checks containment within the build root and existence, accepting directory index files for extensionless paths. It rejects JavaScript URLs and path escapes. It skips HTTP(S)/other protocol-relative external references, mailto/tel/data, and fragment-only references; query/hash suffixes are stripped before local lookup.

It does not fetch external URLs, inspect fragment IDs, parse JavaScript-generated links, cover `srcset`, decode every URL/HTML entity case, or validate the semantics of remote demonstration links. Its regex-based extraction is useful coverage for this simple output, not a complete browser URL model. Documentation cross-links are outside the deployment check and should be checked separately when docs change.

## Regression coverage

Engine tests run with `bun test ./src` in `packages/engine`; [bunfig.toml](../packages/engine/bunfig.toml) preloads a setup file that changes into `test/fixture/`, a minimal app with layouts, `content/_site.md`, and CNAME. Checks tests run with `bun test ./src` in `tooling/checks`. `bun run test` runs both through Turbo.

Tests use disposable filesystems/Git repositories and local server fixtures. The hook test substitutes a small fixture CI command to test index behavior without recursively running production CI. There is no coverage threshold. Server integration tests cover request-time rendering, routing, watcher invalidation, metadata dependencies, error recovery, and explicit port failures. Browser behavior is covered by the separate smoke audit below. There is no external-link monitoring and there are no visual regression baselines or remote deployment smoke tests.

Shell syntax checks do not simulate runtime failure paths. Actionlint and zizmor run in the separate GitHub workflow job, not local CI. A passing local command therefore covers a narrower environment than all remote jobs. Recommendations for addressing relevant gaps are in [maintenance](maintenance-and-snapshot.md), clearly separated from implemented checks.

## SEO and newer regression checks

[check-seo.mjs](../packages/engine/src/check-seo.mjs) validates an app's built `dist/` against current page metadata and the resolved origin. It checks selected exact meta values, title, canonical count, H1/main counts, JSON-LD identifiers and relationships, article facts when a BlogPosting is present, PNG signature/dimensions, sitemap membership, robots sitemap advertisement, and same-origin absolute href existence. See [SEO and environments](seo-and-environments.md) for limits. This is local consistency validation, not a search-engine rich-result test.

[seo.test.js](../packages/engine/src/seo.test.js) covers safe JSON, graph types, ancestors/related ranking, deterministic cards, and rejection of wrong canonical/meta/JSON/PNG data. [site-origin.test.js](../packages/engine/src/site-origin.test.js) covers CNAME changes, environment defaults, and URL rejection. [dev.test.js](../packages/engine/src/dev.test.js) runs a real Vite server and covers lazy rendering, edit recovery, concurrent requests, redirects, crawler files, deleted routes, malformed URLs, and explicit port validation. Comment tests explicitly protect the article-example exception.

## Browser smoke audit

[check-browser.mjs](../packages/engine/src/check-browser.mjs) serves `dist/` with Vite preview and drives Chromium through Playwright. It is not part of `verify`; CI runs it as the Browser smoke job with `bunx turbo run check:browser --only` against the `apps/*/dist` artifact uploaded by the Verify job. Locally, `bunx turbo run check:browser --filter=@pulkit/page` builds first, and `PLAYWRIGHT_CHANNEL=chrome` reuses an installed Chrome. Every route found by walking `index.html` files, excluding `assets` and development trees, is loaded at 1440x900 and 390x844.

Each page must return 200 without uncaught errors, console errors, or failed same-origin requests. It must have one `main`, one `h1`, a language, a title and a responsive viewport; every image must decode after lazy loading is disabled; and the document must not scroll horizontally once fonts and images settle. New-tab links need `noopener` or `noreferrer`, links need an accessible name, IDs must be unique, and the theme toggle must be visible. [axe-core](https://github.com/dequelabs/axe-core-npm) runs WCAG 2.0 to 2.2 A/AA and best-practice rules in both themes and fails on serious or critical violations.

Links collected from the desktop pass must point to a built route or file, use the trailing-slash route form, and name fragments that exist on the target page. Every page must also render its main content and heading with JavaScript disabled.

Interaction checks cover the theme toggle from both light and dark system preferences, persistence across reload and navigation, applying the stored theme before the body renders, matching explicit and system palettes, and toggling when storage access throws. Keyboard checks require the skip link as the first tab stop, a working jump to `main`, a reachable theme toggle with a visible focus outline, and toggling with Enter and Space. Collection-to-entry navigation must animate a view transition normally and must not animate with reduced motion.

The audit covers only Chromium and the local build. It does not compare screenshots, fetch external links, or replace manual accessibility review. Moderate and minor axe findings do not fail the run.
